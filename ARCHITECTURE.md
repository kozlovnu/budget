# Личный бюджет — устройство приложения

## Точка входа
`index.html` — только каркас страницы и список модулей. Главный файл — `index.html`. Модули — обычные скрипты с `defer`: браузер выполняет их по порядку, все они видят общие функции.

Порядок групп: **ядро → расчёты → интерфейс → экраны → подключаемые модули → запуск**.

## Как модули подключаются
Каркас не знает о конкретных экранах. Каждый модуль сам регистрирует свои части в `js/core/app.js`:
- `App.view(имя, функция, {section, group})` — экран; имя совпадает с адресом `#имя`;
- `App.actions({имя: функция})` — реакции на кнопки с `data-act="имя"`;
- `App.change(проверка, обработчик)` — реакции на изменение полей;
- `App.widget(id, {name, icon, sizes, render})` — виджет Главной. `render(ctx, size)` возвращает содержимое или `null`, если показывать нечего. Виджет может жить в своём модуле: «Индекс здоровья» зарегистрирован в игре и пропадает вместе с ней.
- `App.onBoot(db => …)` — своя подписка на базу после подключения; `App.onData(() => …)` — после каждой загрузки данных. Так «Прогноз и факт» живёт в своей коллекции, не трогая `db.js`.

Новый раздел или виджет = новый файл с этими вызовами + строка в `index.html`.

Категории, исключённые из средних трат в день, хранятся в `my.daily.exclude`. Пока их нет, исключаются постоянные категории (по разметке прогноза) и поездки.

Аналитика → Траты: выбранный месяц раскрывается по неделям (`monthWeeks` — пн–вс в границах месяца), неделя — по дням (`spendDays`), день — списком операций. Общий график для таких периодов — `periodBars` в `ui/charts.js`.

Счета группируются по странам или по типам (`my.ui.accBy`). Типы: `ACC_KINDS`/`accKind` в `calc/ledger.js` — карты и прочие → расчётные, депозиты, брокерские и фонды → инвестиционные, наличные. В режиме по типам сверху — структура капитала по этим группам.

Долги: `debtCalc(долг, дата)` — остаток с процентами; `debtMonths(долг)` — по месяцам остаток, тело, накопленные проценты и изменение (выдано, возвращено, начислено). Блок «По месяцам» в карточке долга показывается, если есть ставка и капитализация включена.

Раскладка Главной хранится в `my.ui.home` — список `[{id, size}]`, размер S (1 колонка) или M (2). Пока раскладки нет, показывается стандартный набор (`homeDefault`).

## Данные
- `ops/ГГГГ-ММ` — операции месяца, словарь `{id: операция}`; запись затрагивает только свою операцию.
- `meta/accounts`, `meta/settings`, `meta/rates`, `meta/snaps`, `meta/debts`, `meta/game`, `meta/advice` — служебные документы. Пишутся **только изменённые поля** (`saveMeta` → `metaDiff`). Поэтому правки с двух устройств в разные поля не затирают друг друга. Массивы (список счетов, долгов) база заменяет целиком.
- `forecasts/{id}` — сохранённые прогнозы капитала: `auto-ГГГГ-ММ` (раз в месяц; после сверки на 1-е пересохраняется от сверенных остатков) и `m-…` (вручную). Внутри — 12 месяцев, полосы p10/p50/p90 в рублях по портфелям и курсы каждой точки. Сравнение с фактом (`fcCompare`) берёт капитал на конец прошедших месяцев (`capEndRUB`); сводка точности (`fcAccuracy`) — только по автопрогнозам, горизонты 1/3/6/12 мес.
- Остаток счёта = последняя сверка + операции этого счёта после неё (индекс `balIndex` в `calc/ledger.js`).
- Схема настроек — версия 3 (описание в начале `js/model/settings.js`). Приведение к схеме выполняется один раз при загрузке, а не при каждой отрисовке. Переход со старой схемы делается один раз, после резервной копии «перед обновлением».

## Кэши
Расчёты кэшируются в пределах «эпохи» (`CALC_EPOCH` в `core/app.js`). Эпоха меняется перед каждой отрисовкой и каждым действием пользователя. Прогноз и проверка на истории кэшируются по отпечатку данных (`dataSig`).

## Хостинг и база
Приложение — статический сайт на GitHub Pages; данные — в Firestore (Firebase), вход по почте и паролю (Firebase Auth).
- `js/vendor/firebase.js` — библиотека Firebase, собранная в один файл (`tools/`: `npm install && npm run build`), без внешнего CDN.
- `js/core/firebase-config.js` — настройки проекта Firebase (не секретные).
- `js/core/cloud.js` — слой совместимости: даёт `db.js` прежний интерфейс `doc().set/update/delete/get/acquire` и `collection().onSnapshot/orderBy/limit/get`. Документы пользователя лежат в `users/{uid}/…`. `update` пишется как `setDoc(…, {merge: true})`: вложенные объекты сливаются, `null` удаляет поле. Массивы в массивах заворачиваются в `{__arr: […]}`, пустой ключ — в `_~empty` (Firestore их не хранит). `acquire` — блокировка через транзакцию. Там же скачивание файлов (на iPhone — меню «Поделиться»).
- `js/core/auth.js` — запуск: проверка сеанса, экраны входа, регистрации и активации по коду, выход (с очисткой копии базы на устройстве), регистрация сервис-воркера.
- Доступ по приглашению: `invites/{код}` заводит владелец в консоли; `members/{uid}` создаётся при регистрации или активации и только с действующим кодом (проверяют правила); данные `users/{uid}/…` доступны лишь участнику. Без сети отметка об активации берётся с прошлого запуска (localStorage).
- `firestore.rules` — правила доступа: коды приглашений, активация, только своя папка.
- `sw.js`, `manifest.webmanifest` — установка на экран «Домой» и запуск без сети. Данные без сети берутся из кэша Firestore, правки уходят при появлении связи.
- `js/features/rates-auto.js` — курсы ЦБ РФ на 1-е число (зеркало cbr-xml-daily.ru): при открытии дозаполняет пустые месяцы до текущего, ручные и файловые не трогает.
- Разбор PDF-выписок и консультант работали через Claude (`SAMPLE`) и здесь отключены; импорт Excel/CSV работает.
- Резервные копии включают сохранённые прогнозы (`forecasts`) и данные игры; восстановление из файла переносит и их.
- Демо-режим (`js/features/demo.js`): флаг в sessionStorage; `boot()` подключает вместо Firestore базу в памяти с тем же интерфейсом и вымышленными данными за полгода (счета в сумах, рублях и долларах, сверка на 1-е число, курсы). В настоящую базу ничего не пишется. Вход — приветствие пустой базы или Настройки → О данных; выход — «Начать со своими».
- Пустая база показывает приветствие (`Demo.welcome()`): демо, первый счёт, перенос из резервной копии. Экраны `backups` и `about` открываются и без счетов.
- Гид «С чего начать» (`js/features/guide.js`) — карточка вверху Главной: шаги отмечаются по данным (счета, сверка, операции, доход, лимиты, установка на экран «Домой»). Скрытие — `my.ui.guide = "off"`, вернуть — Настройки → О данных.
- Тесты слоя базы: `node tests/cloud.test.js` (модель Firestore в памяти).
